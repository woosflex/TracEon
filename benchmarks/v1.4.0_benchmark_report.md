## Section 1: Benchmarking Methodology

### Test Matrix
- **File Sizes**: 10 MB, 100 MB, 500 MB, 1000 MB
- **Data Types** (8 scenarios per size):
  - WGS (Illumina short reads): 150 bp, FASTQ format
  - WGS_GZ: Same, GZIP-compressed
  - PacBio (long reads): 15,000 bp, FASTQ format
  - PacBio_GZ: Same, GZIP-compressed
  - Nanopore (ultra-long reads): 30,000 bp, FASTQ format
  - Nanopore_GZ: Same, GZIP-compressed
  - RefGenome (reference sequences): 1,000,000 bp, FASTA format
  - RefGenome_GZ: Same, GZIP-compressed

### Metrics Collected
- **Load Time (s)**: Time to decompress (if needed) + parse entire file
- **Restore Time (s)**: Time to reload from binary cache (v2 LZ4 format)
- **Record Count**: Actual number of sequences loaded
- **Peak Memory (MB)**: Maximum RSS during operation
- **Lookup Throughput (ops/s)**: Random access performance (500M lookups or size-based volume)
- **Compression Ratio**: File size reduction (original file size vs binary cache size)

### Comparative Tools
- **SeqTK**: Sequence toolkit for FASTQ validation
- **SeqKit**: Go-based bioinformatics toolkit
- **BioPython**: Python reference implementation
- **PyFastX**: Optimized Python FASTA/FASTQ reader
- **TracEon**: This library

## Appendix F: Known Limitations

1. **RAM Latency Wall**: 3–4x throughput degradation when dataset exceeds L3 cache (16–32 MB). This is **hardware physics** (100ns RAM latency vs 10ns L3), not a software limitation.

2. **Single-Node Only**: No distributed caching (planned for v2.1.0). Target: Local workstation/server workloads.

3. **Immutable After Load**: Cannot incrementally update cache post-load (by design for lock-free reads). Workaround: Reload entire file via binary cache mmap.

4. **IndexMode Switch**: Requires reconstruction — cannot convert GenomeIndex ↔ NGSIndex without re-parsing the file.
